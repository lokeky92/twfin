# 改善提案：ETF-IMPROVE-20261122-001｜建立跨市場底層資產實體正規化映射（解決 0050+SMH 台積電 2330 vs TSM ADR 重疊度算成 0% 漏洞）

- **提案 Agent**：`AGENT_04, AGENT_01, AGENT_05`
- **核准狀態**：`PENDING_APPROVAL`（⚠️ 未經使用者明確批准前，嚴禁執行修改）

## 1. 目前問題
目前 `computePairwiseOverlap()` 與個人投資組合穿透診斷器僅比對 `constituent_code` 字串是否完全相同。台灣 ETF（0050/006208/0052/00891）將台積電記為 `'2330'`，而美國半導體 ETF（SMH）與全球 ETF（VT）將台積電 ADR 記為 `'TSM'`，導致使用者同時勾選 `0050 (56.8% 台積電)` 與 `SMH (13.2% 台積電 ADR)` 時，系統算出兩者持股重疊度為 `0.0%`，嚴重低估跨國單一企業集中風險！同理，`00679B` 與 `TLT` 底層同為 20 年美債、`00635U` 與 `GLD` 同為黃金曝險亦未貫穿。

## 2. 問題證據
• SQLite `etf_holdings` 實證：`0050` 持有 `2330` (56.8%)、`0052` 持有 `2330` (63.2%)、`SMH` 持有 `TSM` (13.2%)。
• 程式碼實證：`frontend/index.html` L4636 `mapA[h.constituent_code] = h.weight_pct` 未做實體正規化，實測 `computePairwiseOverlap('0050', 'SMH')` 回傳 `overlapPct: 0.0`。

## 3. 建議修改方式與程式碼差異預覽 (Diff Preview)
1. 建立跨市場底層實體正規化映射函數 `normalizeConstituentEntity(code, name)`：將 `'2330'` 與 `'TSM'` 統一映射至 `'ENTITY_TSMC (台積電 2330 / TSM ADR)'`；將 `'00679B'` 與 `'TLT'` 底層統一映射至 `'US_TREASURY_20Y'`；將 `'COMEX_GOLD_FUT'` 與 `'LBMA_GOLD_BULLION'` 統一映射至 `'ENTITY_GOLD (黃金資產曝險)'`。
2. 在圖 6 重疊度熱力圖與個人投資組合穿透診斷器套用正規化實體比對，並依 Agent 05 審查要求，於 UI 明確標註『基於前十大核心持股＆跨國 ADR 實體穿透計算』。

```diff
--- a/frontend/index.html
+++ b/frontend/index.html
@@ -4634,6 +4634,13 @@
+    function canonicalEntityKey(code, name) {
+      if (code === '2330' || code === 'TSM') return { key: 'ENTITY_TSMC', label: '台積電 (2330現股 / TSM ADR)' };
+      if (code === 'COMEX_GOLD_FUT' || code === 'LBMA_GOLD_BULLION') return { key: 'ENTITY_GOLD', label: '黃金資產 (期貨/實體條塊)' };
+      return { key: code, label: name };
+    }
```

## 4. 預期效果
勾選 `0050` 與 `SMH` 時，重疊度熱力圖將正確顯示 **`13.2%` 跨國台積電重疊警示**；個人投資組合若同時持有 `0050 + 0052 + SMH`，將精準穿透累加台積電總曝險並觸發情境 B 半導體集中度紅燈警告。
